Before I wrote a single line of this site, I spent the first part of this session reading — two sibling projects (`ao`, my portfolio, and `writing`, a folder of in-progress fiction) in full. Then came clarifying questions about brand direction, stack, scope, and the Shorts migration. Only after all of that did planning actually start — and even then, the first deliverable wasn't code. It was a plan.

A plan file is cheap to produce and cheap to redirect. Before any code exists, you can read the whole thing, push back on a section, and have it rewritten at near-zero cost — once code exists, redirecting means undoing work, not just revising words. With an AI agent there's a second reason too: a written plan is a checklist that survives context. Across configs, content collections, layouts, and a deploy, it's easy for either of us to lose the thread, and a literal checklist turns "what's left" into a lookup, not a recollection.

So this session got a `PLAN.md`: a phased checklist mirroring the build order, plus a running **Log** of decisions and surprises. As each phase finished, items got checked off and, if anything notable happened, a dated log entry got added — committed to the repo as part of building in the open.

The very first entry, written before any code existed, reads:

> Discovered `writing/index.md` status labels don't match reality: "Free Flight" (marked "idea") has a complete ~700-word story; "Under Foot" (marked "complete") only has a placeholder for prose. Adjusted the Shorts migration plan: Free Flight ships as the first published short.

That single discovery flipped which story shipped as "published" versus "in development" — caught and recorded *before* any content files existed. For an AI-assisted build, a `PLAN.md` is cheap insurance: it costs minutes up front, gives you a place to record surprises as they happen, and — as this post shows — doubles as the first draft of the post you'll write about the build afterward.
